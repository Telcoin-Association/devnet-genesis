## C. digest_order_hold.rs (before_store, kill and control now run the always-on rule instead of the adaptive one)
What the before_store test needs: on the hooked node, digests re-queued with cause `canceled` (`check_form`, `:1362-1363` via `requeue_cause`, `:261-265`), `HEADERS_HELD > 0` with `held > 0` lines (`:1355`), `OUT_OF_ORDER == 0`. The control needs `OUT_OF_ORDER > 0` (`:1377`). Where the cancel comes from: certifier.rs:523-534 at de075ab78. The `before_store` hold sits after the certificate has FORMED, and a newer own header that arrives during the 5 s hold returns `DagError::Canceled`. The cancel therefore needs two things. (a) The held header gets its quorum of votes. The always-on rule makes this at least as likely as the adaptive one, because the header names a block a quorum holds. With HOOKED=0 unslowed and only SLOWED=2 late, the quorum {0,1,3} never needed node 2 in either form anyway. (b) The next own header reaches the certifier within 5 s. That depends on the proposer collecting the three other validators' round-r certificates, which the exec-block rule does not gate. Under the adaptive form a hook cancel opened the window, so most of the run already used the quorum rule. I see no mechanism by which always-on removes the `canceled` path. The watch item for the first run is `:1362-1363` for `hold_before_store` and `:1377` for `hold_off_control`. The kill now runs always-on with `after_store`, the path the base `_always` test already ran.

## E. What the commit loses, and the upgrade question
The writer's list is accurate. Lost: (i) the control's "fast node certifies ≤ 0.85 without the rule", which can only be expressed with an off arm (the base measured 0.61-0.74 against the kept 0.93, so the kept threshold still separates the two); (ii) the adaptive arm; (iii) the mixed fleet. The list omits that the mixed fleet also restarted a switched node across epochs 1-3 at gc depth 50, but that part is uniform-fleet behaviour that upgrade.rs (`restart_validator`, `cross_epoch_boundary`) and epoch_close_forms still cover.
**`make test-upgrade` does not cover "an old voter receives a header that names an older block".** upgrade.rs at de075ab78 has no `EXECUTION_DELAY_ENV`, no slowed node and no read of `exec_basis`. All four validators execute at the same speed under `drive_light_tx_load`. An upgraded proposer therefore names its own tip (`exec_basis=tip`) almost always. Whether an old (main) voter ever votes on an older-block header is chance, and nothing asserts it. The kept voter-side unit tests (network_tests.rs) exercise the new binary's voter, not main's. This is a limit the pull request must state, unless upgrade.rs gains an execution delay on the upgraded nodes in its mixed phase.

## Findings
### Medium
- **M1. The commit body overstates the replacement.** de075ab78 says "test_mixed_switch_fleet_is_one_chain goes: a fleet of old and new binaries is what `make test-upgrade` runs". That is true of the fleet, but the one case only the mixed test asserted (a certified header of a new node that names an older block, voted by a node that lacks the rule; base `MIN_MIXED_OLDER_CERTIFIED`, `:530`) is not exercised by upgrade.rs. Change: state the limit in the PR body. Optionally, in a separate follow-up, give the upgraded validators `EXECUTION_DELAY_ENV` on the old ones during upgrade.rs's 2 PREV + 2 CURRENT phase and count `exec_basis!=tip` certified headers.
### Low
- **L1.** The guard "STACK_SWITCHES_ON and STACK_SWITCHES_OFF name the same switches" went with `VoteForm::switches` (base epoch_close_forms.rs `:299-306`). `stack_overrides()` (`:251-257`) uses ON alone, so a switch added only to OFF would run at its default unnoticed. Moot once R4 empties both lists. Otherwise move the guard into `expected_switches`.
- **L2.** exec_block.rs:246: `read_run`'s `run` is always 0 now (only the mixed test read run 1). Fold it into `read`. `HeaderWindow` and its methods stay `pub(crate)` (`:229,241,288,306,311`) with no user outside the file.
- **L3.** exec_block.rs:312: `describe`'s `count` helper takes a `fn(&ProposedHeader) -> &str` for its single remaining use (basis).
- **L4.** epoch_close_forms.rs:59 "The proposer fix's floor" frames the behaviour as a fix. Write "The proposer's floor (`QUORUM_EXEC_BLOCK_FLOOR_ENTRIES`)".
