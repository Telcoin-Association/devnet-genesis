# HB8-5 — the endpoint sampler also reads each node's clock offset and CPU counters

Common brief: `tasks/bench8/briefs/hb8-common.md`. Checkpoint `tasks/checkpoint-bench8-HB8-5.md`. Budget: 25 tool calls. The inventory this follows: `tasks/bench8/saved-measures-inventory.md` (read its verdicts 1 and 2).

Five of the bench 7 analyses compared times across nodes without knowing how far the nodes' clocks were apart, and one could not tell a slow validator from a starved one because host steal time was not saved. `tasks/bench8/orch-endpoint-sampler.sh` already opens one session per node per round (every 60 s: `gcloud compute ssh … --command 'curl … :9101/metrics | gzip -1 | base64 -w0'`, near `:57-59`) and saves the node's metrics endpoint. Add two host readings to that same session, so no second session per node is opened:

1. **Clock**: the node's offset from its time source. Read which time daemon the bench nodes run from the harness, not by guessing: `grep -rn -i 'chrony\|timesyncd\|ntp' benchmark/*.sh common/ 2>/dev/null | head` (the node boot image is Ubuntu 24.04; its startup script may install chrony). Emit, in order of preference and whichever exists on the node: `chronyc -n tracking` (the lines `Last offset`, `RMS offset`, `System time`), else `timedatectl timesync-status` (the `Offset` line), else the word `none`. Never fail the session because the command is missing.
2. **CPU counters**: `head -1 /proc/stat` (the aggregate `cpu` line: user nice system idle iowait irq softirq steal …, running totals in jiffies) and `getconf CLK_TCK`.
3. Save them beside the metrics snapshot of that node and round as a small text file (same naming with another suffix; say the exact names), framed so that the metrics payload and the host readings cannot be confused (the session's output today is one base64 blob: keep it one line, and put the host readings on later lines behind a fixed marker line; the script splits on the marker). The metrics file must stay byte for byte what it is today; a session whose host part is missing or malformed still saves the metrics and notes `host=missing` in the round's log line.
4. The script's header says it is read-only and reads nothing else (near `:8`, `:14`): update the comment: still read-only, it now also reads the time daemon's status and one line of `/proc/stat`.
5. Tests in `tasks/bench8/tests/` with the fake `gcloud` (its `compute ssh` answer is driven by `ssh.json`): a round with the host block (both files written, the metrics file identical to today's), a round without it (metrics saved, `host=missing`), a round with `none` for the clock.
6. A reader for the analysis: `tasks/bench8/orch-host-readings.py <samples dir>` printing one TSV row per node per round: utc, node, clock_offset_s (signed, empty when none), clock_source (chrony | timesyncd | none), steal_jiffies, total_jiffies, steal_share_since_previous_round. Test it on the fixture files your tests write.

Yours: `tasks/bench8/orch-endpoint-sampler.sh`, `tasks/bench8/orch-host-readings.py` (new), `tasks/bench8/tests/test_orch_bench8.py` and `tasks/bench8/tests/fakes/fake_gcloud.py` (extend), a fixture directory under `tasks/bench8/tests/fixtures/` if you need one. Nothing under `benchmark/` or `common/`.

Gates: `bash -n`, `shellcheck -S warning`, py_compile and the 3.9 grammar check on what you changed; `python3 -m unittest tasks.bench8.tests.test_orch_bench8 tasks.bench8.tests.test_orch_scripts` green (run in the foreground, one call).
Hand back: files with +/- counts, the saved file names, the marker line and the TSV columns verbatim, which time daemon the nodes run and where you read it, the gates.
