## Findings

### M1 (Medium): finalize requires a trusted-nodes map by role, not "when the map exists"; with no rpc node native finalize cannot pass
- File: `devnet-finalize.sh:421-424` (`_has_trusted_map`), used at `:1249` (gate `_maps_verdict`), `:1436` (`--trusted-nodes` in finalize_args), `:875` (A6 want).
- Scenario: `TN_ADMISSION_VIA=native`, a fleet with no `rpc` entry (or one whose rpc entry is dropped). `devnet-network-config.py maps` correctly writes no `*.trusted-nodes.yaml` (docstring and `cmd_maps`: "none at all without an rpc node"), and `devnet-network-config.sh` installs none. Finalize then fails every validator and observer at the readiness gate with "local …/node1.trusted-nodes.yaml missing"; if the gate were passed, it would hand setup-node.sh `--trusted-nodes` for a file that does not exist, and A6 would want `TRUSTED_NODES_FILE=/etc/telcoin/trusted-nodes.yaml`.
- Verified by harness (h1): `maps` without node6 writes 5 bootstrap maps and no trusted map; `_maps_verdict 0` -> "admission maps not as rendered: local …/node1.trusted-nodes.yaml missing", rc 1; `_has_trusted_map 0` rc 0.
- Why wrong: contract §9 Z1 says `--trusted-nodes` "when the map exists"; the renderer and the installer follow the rule "validator/observer AND the fleet has an rpc node", finalize follows "validator/observer". The live fleet has rpc-6, so launch 2's deploy does not hit it; any other native fleet (or a run with the rpc entry removed) does.
- Fix: make `_has_trusted_map` the renderer's rule: `case "${NODE_ROLES[$1]:-}" in validator|observer) [ -n "$(tn_indices_by_role rpc)" ] ;; *) return 1 ;; esac` (keeps a missing file a gate failure when one is expected).

### M2 (Medium): the finalize gate cannot see maps that are stale against the committee it is about to stage
- File: `devnet-finalize.sh:1244-1265` (`_maps_verdict`).
- Scenario: maps rendered + installed (step 7); then keygen is re-run on a host (or genesis rebuilt), step 6 and the release prepare/sign are redone, step 7 is not (`--only 6`, then `--from 10`). Local and host maps are equal, both stale. The gate passes ("installed = local by sha256"), finalize stages the NEW committee.yaml and hands setup-node.sh the OLD bootstrap-peers map, which becomes the node's `--bootstrap-peers` and `committee_peers`. A changed BLS key makes the node exit at epoch 0 ("committee_peers: missing validator …", A-5); a changed address/key makes it dial the wrong peer. It is noticed only after the node started: inside setup-node's start check, or in phase B (A3 `validate --native` recomputes the expected maps from the current committee and fails), i.e. after `--start-all` when staged.
- Verified by harness (h1, run2.sh): maps rendered from native/committee.yaml, then node3's primary address changed in committee.yaml and its node-info; `_maps_verdict 0` with gate = installed sha -> rc 0 "installed = local by sha256"; a fresh `maps` run on the new committee writes a different node1.bootstrap-peers.yaml.
- Why wrong: the gate's job (header step 1) is to stop a node before it is finalized with a bad admission input; the release signature covers committee/genesis but not the maps, so nothing else ties the maps to the staged committee.
- Fix: once per run, before phase A (native only): `python3 "${NC_PY}" maps "${NC_CTX[@]}" --out-dir "${WORK}/maps-now"` and `cmp` each node's local map against it; on a difference, stop with "local admission maps are stale against genesis/committee.yaml: run ./devnet-network-config.sh --yes". Local only, no ssh.

### M3 (Medium): `devnet-network-config.sh --yes` on a finalized host reports ok and says "finalize writes it from the maps", but finalize refuses that host

- Traced line by line (install mode returns `NC_RESULT=ok` before any comparison of the live network-config).
- Why wrong: the message names a way forward that does not exist; the way that does exist without rebuilding the host (tn-node-deployment `edit-config.sh --set bootstrap_peers=<file>` and its admission / trusted-nodes setters, which re-render network-config and restart the node, facts tnd-node §5) is not said by either driver.

At minimum, replace the note's text.
