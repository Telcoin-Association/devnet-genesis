2. Row 2: the runbook's command sends 3 packets. Against a baseline of about 160 accepts/s and 1 drop/s, 3 packets cannot be seen. On mainnet use N of 500 or more and read the counters every 2 s in one ssh session on the target, as done here (IAP ssh adds several seconds per call).

4. Row 8: 16 parallel curl processes, each with its own TLS handshake, reached 70 requests/s. A bucket of 200 that refills at 100/s allows about 628 requests in 4.28 s, so no 429 could happen and the per-client-IP limit was not exercised. The reads did count at the gateway: query `forwarded` rose by 305 (300 from the burst, 1 from txgen, a few others). So reads are not passed to rpc-6 uncounted. Exercising the limit needs a faster client: one keep-alive connection, or a load tool, under 32 connections. Not run here, since the brief allows one burst.
