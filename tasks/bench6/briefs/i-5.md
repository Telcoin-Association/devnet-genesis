## Background
In bench 5 the engine ran execute (479 ms per output) and persist (1,167 ms) strictly in sequence. Pipelining them — output N+1 executes on N's in-memory state while N's persist runs — would make the cycle max(execute, persist) instead of the sum (×1.42 at bench-5 numbers). The sketch and its seven invariants are in /home/drtnarg/coding/telcoin/devnet-genesis/benchmark/private/bench6-prep/design/design-node-fixes-for-bench-6.md (§B topic 10). It ships behind the switch `pipelined_persist` (a top-level `Parameters` bool, default false = today's strictly sequential path, byte-identical), and only if its go/no-go tests pass.
