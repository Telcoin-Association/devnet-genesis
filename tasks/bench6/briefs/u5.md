## Why
At loaded epoch boundaries in bench 5 (r20261107-1504) the node logged about 1,400 `Failed to track spawned task` errors: while the
epoch-close path runs, nobody drains the task manager's tracking channel, it overflows, and the overflowed tasks (and up to 1,000
still queued) escape `abort_all_tasks` — they end only when the manager is dropped at `run_epoch`'s return, after the epoch's pack
is sealed. Separately, a member that reaches the close late skips the comparison of its `final_state` with the epoch record, and
with the proposer fix of this round (headers name an older block) that comparison becomes the only immediate divergence check at
the boundary.

## Deliver
1. `TaskManager::track_while(fut)`: drives `fut` to completion while draining `new_task_rx` and polling finished tasks, with none of
   `until_exit_internal`'s exit conditions and without ever dropping `fut` before it completes. Behind `epoch_close_task_drain`
   (default false = today's code path): the boundary handler awaits close, record and export through it, and the task bookkeeping
   runs before `wait_for_exit` / `abort_all_tasks`, so every task spawned during the close is tracked and aborted with its epoch.
2. Behind `epoch_record_state_check` (default false): at the `final_state` site, compare this node's final execution state with the
   epoch record and HALT the node on a mismatch (fail-stop, with an error line that names both values), instead of skipping the
   comparison when the node arrives late. When the node has no executed block to compare (the recent-blocks ring is empty), skip the
   comparison, count it, and log one warn line — and say in your hand-back exactly what a record written in that state contains
   today (the review noted an empty ring yields block (0, zero hash)); do not change that behaviour, report it.
3. Gauges and counter (no switch; exact names in your hand-back): the engine backlog in outputs when the close is detected, the
   lag between the closing output being sequenced and the close being detected, the drain's duration in seconds, and
   `epoch_record_vote_skipped_total{reason}` with a reason per skip path that exists today.

## Tests
`task_manager.rs`: tasks spawned while `track_while` runs are tracked (no overflow at 2,000 spawns), a finished task is reaped, the
future's output is returned, the future is not cancelled when the channel closes or a task panics. `close_epoch`: a mismatch halts
with the switch on and is skipped as today with it off; the empty-ring case. With both switches off the existing node tests pass
unchanged.
