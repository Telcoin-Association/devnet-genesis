## Why
In bench 5 (r20261107-1504) a voter that had not yet executed the block a header names waited up to 1 s for it WHILE HOLDING the
per-author vote lock, so requests from the same author queued behind each other and each waited its own second (`lock_ms` in the
seconds), and stale rounds were served after newer ones had arrived. The fix: wait before taking the lock, refuse requests that a
newer request from the same author has superseded, and never wait a second time under the lock.

## Deliver (behind `vote_queue_fix`, default false = today's path unchanged)
1. Before the author lock: (a) a per-author high-water mark of the (epoch, round) of RECEIVED requests, set only after the author
   check has passed and only for rounds within `committed + gc_depth` (a far-future round must not poison it); a request below the
   mark is refused at once with a new recoverable refusal `SupersededRequest`; (b) a bounded wait for the named execution block
   (`timeout(VOTE_EXECUTION_WAIT, …)`, result ignored).
2. Under the lock, `vote_inner` does a ZERO-WAIT check of the execution block: a database miss is "behind" (`ExecutionBehind`), never
   a fork; a present block with a different hash stays the existing fork/unknown-result refusal. A request must never wait twice.
3. `SupersededRequest`: add it to the RECOVERABLE arm in `message.rs` by hand — the mapping ends in a catch-all that would silently
   turn a new variant into a fatal "request for requested vote" error — and give it penalty `None` in `error/network.rs`. Check the
   requester side reads it as retryable (the certifier resends every 250 ms up to six times, then backs off; a newer own header
   cancels the request): cite the lines in your hand-back.
4. Metrics and log: `VoteStage::PreLockWait`, outcome label `superseded`, and `prelock_wait_ms` on the existing `vote path timing`
   line (the field is present with 0 when the switch is off, so parsers see one shape).
5. Separate commit, `Topic: tracker-drain`: the gauge `tn_primary_epoch_entry_rounds_behind`, set in `behind_consensus`, = how many
   rounds this node is behind the committed round it observes when it enters an epoch (the design's "entry gauge"; the benchmark
   aborts the admission-bound arm when it reaches 30). No behaviour change, no switch.

## Tests (unit, paused clock)
Five queued requests from one author whose block is not yet executed are all answered in about one second in total, not five;
a stale round is refused at once with `SupersededRequest` and no wait; a far-future round does not move the high-water mark; an
unauthenticated or wrong-committee request does not move it; the zero-wait check under the lock (present, missing → behind,
different hash → the existing refusal); `SupersededRequest` is recoverable and carries no penalty; with the switch off the existing
vote tests and every equivocation test pass unchanged (run the whole package).
