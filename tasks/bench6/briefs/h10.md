## Why
Bench 5 lost 24.7 % throughput because MDBX under WRITEMAP wrote 4.3× the device bytes of the pages it dirtied. The investigation's ranked cause: each node ran its load in a re-opened database whose random-access advice covered only the genesis pages, and large folios were built in the rest by one of two routes (mmap read-around, or libmdbx's multi-page prefault write). The node fix applies the advice to the whole map. Before eleven machines are paid for, ONE machine of the fleet's exact shape (same machine type, disk type and size, pinned boot image, kernel) must show whether that fix works on the GCE kernel, which route matters there, and that the new persist sampler is safe beside a live writer. That is this probe: one VM, about an hour, created and deleted by one driver.
