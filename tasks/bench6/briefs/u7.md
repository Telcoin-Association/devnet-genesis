## Why
In bench 5 (r20261107-1504) a batch whose report to the primary failed at an epoch boundary was rebuilt with the same digest about
85 times, the same digest reached headers more than once (5 duplicate digests), and resent transactions executed twice (37,683
`nonce too low` skips). The worker should not report a digest it has already reported.

## Deliver (behind `digest_dedupe`, default false = today's path unchanged)
Before `verify_batch` on the own-batch path: if the digest is already in the own-batches cache (already reported), return `Ok`
without verifying or reporting again, and count `tn_worker_duplicate_digest_suppressed_total`. Decide and document, from the code,
what "already reported" must mean so that a batch whose report FAILED can still be reported on a retry (the cache entry must
reflect a successful report, or the dedupe must not apply to a failed one): the boundary case in bench 5 was a report that failed
and was retried — do not turn a lost report into a silently dropped batch. If the worker cannot read the switch without a
constructor change you do not own, stop and hand back.

## Tests
A digest reported once is not reported again and the counter moves; a digest whose first report failed IS reported on the retry;
switch off → both reports go out as today; the cache's bound/eviction is unchanged (no unbounded growth).
