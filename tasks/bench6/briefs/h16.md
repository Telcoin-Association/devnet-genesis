## Why

gaps, each of which can make a row say something the run did not show.

## Deliver
1. **A counter's increase over an arm's window.** The summary reads counters from `metrics.json` as cumulative points per node
   (kind `counter_max`, written by the generator repo's `bench/collect-gcp-metrics.py`) and adds `max(0, y − x)` between
   consecutive points. That loses (a) whatever a counter reached between a node restart and its first scrape — arms restart
   nodes — and (b) the first value of a counter that is created at first use inside the window (the admission refusal
   counter is such a one: it exists only once the bound is enabled). The collector's own `window_count` rule handles a drop
   by adding the new value: use the same rule (a value below its predecessor is a restart: add the new value; a series
   whose first point lies inside the window and whose node was already running starts from 0). Read the collector's rule
   and its tests first so the two agree; pin both cases in `test_arms_summary.py`.
2. **The recovery-pool arm must be the pool it claims.** If the dedicated pool fails to build, the node warns once
   (`signer recovery pool failed to build`) and recovers on the global pool for the rest of the process, while the switch
   line and gauge still read 3. As the summary already does for the MDBX advice (`advice_on_by_node`, `storage_note`): a
   node is on the dedicated pool only if its `signers recovered` lines in the window carry `pool=dedicated` and its log has
   no such warning since the arm's begin; otherwise the row carries a note naming the node. Take the exact message and
   field names from the node code (`/home/drtnarg/coding/telcoin/telcoin-network-b6/crates/engine/src/recovery.rs`, read-only)
   and add both lines to `benchmark/tools/log-shapes.txt` (the prefilter list), with the size effect of `signers recovered`
   (it is per output) stated in the hand-back.
3. **Apostrophes.** The node writes its logs with a logfmt formatter that escapes `'` as `\'`. Find every message string the
   summary and the other tools under `benchmark/tools/` and `benchmark/report/` grep that contains an apostrophe, and make
   each match what a log line really holds (as `log-shapes.txt` now does for the final-state halt: an apostrophe-free
   substring). Report the list; if there is none, say so.
4. **Housekeeping.** (a) The generator repo's README table of Prometheus kinds gets a row for `counter_max` (query key
