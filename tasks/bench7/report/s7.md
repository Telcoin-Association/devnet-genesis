### Corrections made during the program

- The kill came earlier into the load in bench 7, not later: 817 s and 1,121 s into blast 2's mixed phase [C Q1.38] against bench 6's 1,477 s and 1,393 s; an earlier wording said "later", and the bench 6 comparison's shape check corrected it [D 15].
- Run 7b's partial Prometheus series are on three validators and the observer, not two; validator-05's gap ends at 18:40:00Z, not at its kill [RF 7b].
- Run 7b's idle between the deploy and the blast is 5.7 min, not 5.6: the manifest ends the deploy at 17:40:41Z, the chain's line at 17:40:48Z [RF 7b].
- The rejoin mark's rule was corrected for run 7b (a start-up sample can read `cvv_active` = 1); run 7a's mark was not re-made [D 21].
- The certification analysis of run 7b removed four sentences carried over from run 7a that its numbers do not support (among them "voters whose own headers were lost kept prelock p95 at 0": voter 01 lost headers and had 1,001 ms) and corrected two checkpoint figures from the slots [O 19:56Z].
- The disk analysis of run 7b replaced three sentences from run 7a: commit time per transaction against the cap share runs 40.3, 25.1, 27.5 and 32.5 µs by bin, so "did not rise" is not said, and the cap share and the store's growth are not told apart [O 19:58Z].
- The engine analysis of run 7a removed six statements its JSON does not carry: "never caught up" became a per-bucket mean lag (validator-05 516 to 541 outputs behind in buckets 4 to 7), and "near capacity" for blast 1 and two code readings went [O 20:02Z].
- The rounds analysis of run 7a renamed its file's top-level keys to run 7b's; the keys inside each question still differ [O 20:01Z] [D 27].
- Run 7b's endpoint sampler holds all 11 nodes in 89 of its 94 rounds, not 88 as the run's first notes counted [O 19:28Z]; the figure-check counted the sampler's log.
- The lost attempt's idle after the idle check's stop is 3.8 min (225 s, 16:04:23Z to 16:08:08Z), not 3.7; the figure-check took both times from the chain log and the blast log.
- The commit notice (§4.5): it is sent whenever a committed sub-dag holds any header, not only when it holds an own header, as this report and the far-validator analysis first said; a notice with no own round re-queues nothing, so the effect stated is unchanged. Found by the figure-check of the defect report, which read the lines at main 33b727fce.
- The far-validator analysis says run 7b's loss file holds no first-proposal-to-execution figure; it does (it was added after that analysis was written), and this report's table uses it, so all four runs share one latency start.
