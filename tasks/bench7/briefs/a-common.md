## 1. Run facts (the orchestrator fills this per run; cite, do not re-derive)

The shape is bench 6 run 2's (`tasks/bench6-run2-analysis-brief.md` §1): ten validators and one observer, `c3-highcpu-8`, 100 GB Hyperdisk Balanced at 20,000 IOPS and 800 MiB/s, generator 62bbd5f, the arm applied at deploy step 7 before the first start, no host step.
Launch env: `benchmark/launch/bench7-always.env` or `benchmark/launch/bench7-adaptive.env` (they differ only in `BENCH_ARM_FILE` and the header).

Each configuration runs ONCE: every comparison says "one run each" and makes no significance claim.

Filled per run in `tasks/bench7/<run>/run-facts.md` (run 7a `r20261115-1131`, form `always`; run 7b `r20261115-1450`, form `adaptive`): image digest and node commit, storage engine, deploy times, the arm and its sha256, the fsync probe, every blast's real phases, the kill, the start and the observer restart, the end-of-run checks, the export's window and check lines, teardown and archive, and under "By hand" what went wrong.
