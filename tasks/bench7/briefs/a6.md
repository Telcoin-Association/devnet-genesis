# A6 — the disk under tn-lmdb at 20,000 IOPS (bench 7, one run)

Unit `A6` (analysis, opus, read-only on code and results). Read `tasks/bench7/briefs/a-common.md` first.
Checkpoint `tasks/checkpoint-bench7-<tag>-A6.md`; output `benchmark/private/bench7-<run>/A6/`; `<big>` = `benchmark/work/bench7-scratch/<tag>-A6/`; budget under 200k tokens.
On Hyperdisk the write COUNT and the syncs bind, not the bytes: every table gives the write count and the sync count first, the write size and the bytes beside them, and the commit time beside any of them.
Inputs: `persist/<node>.csv` (30-s rows; 300-s rows for the slower columns), `persist/<node>.folios.txt`, `metrics.json`, the export, the `persisted output` lines of the prefiltered logs, `arms.json` (tn-lmdb and disk blocks; A1).

## Questions (tick each; checkpoint after each)

1. To be checked on the first run, before any table: the CSV's header line against `benchmark/tools/persist-csv-header.txt`; the eight tn-lmdb columns (`tn_lmdb_dat_size_bytes`, `tn_lmdb_dat_allocated_bytes`, `static_files_size_bytes`, `static_files_files_total`, `tn_lmdb_used_bytes`, `tn_lmdb_dat_resident_pages`, `tn_lmdb_dat_vma_bytes`, `tn_lmdb_dat_rr_bytes`) filled on every node, the MDBX columns present and empty (a column without a source on tn-lmdb is written empty, rules "Harness units"); which tables and labels `reth_db_table_pages` and `reth_db_table_entries` carry on this store (the export says tn-lmdb reports them under reth's names).
2. Per blast and per minute of B2, per node and as the median over the validators (validator-05 apart in B2): device writes per second against 20,000 (the persist CSV's `/proc/diskstats` counters; `arms.json` `wr_iops`, `iops_pct_of_cap`, `binds`), cross-checked with `metrics.json` `.gcp[<node>].disk_write_ops_per_sec.points` (`wiops_minutes.py`); writes per transaction (`wr_ops_per_tx`); syncs per output and per transaction (`flush_ops_per_output`); write size (`wr_kib_per_op`); device time per write and per sync (`wr_ms_per_op`, `flush_ms_per_op`); then bytes per transaction (`wr_bytes_per_tx`) and MiB/s against 800.
3. The commit and the save against the device: `commit_ms_output`, `save_blocks_ms_output`, syncs per commit, and the least device time the caps allow one output's writes (`cap_floor_ms_per_output`): how much of the commit the device's write limit explains.
4. The store: growth of `tn_lmdb_used_bytes` + `static_files_size_bytes` per transaction (`store_growth_bytes_per_tx`) and per output; `tn_lmdb_dat_size_bytes` against `tn_lmdb_dat_allocated_bytes`; `static_files_files_total`; the store's size at B2 start, B2 end and the run's end; `reth_db_table_entries` and `reth_db_table_pages` per table at the end, `reth_db_freelist`, `reth_db_page_size`.
5. The page cache: `tn_lmdb_dat_resident_pages`, `tn_lmdb_dat_rr_bytes` over `tn_lmdb_dat_vma_bytes`, major faults per minute (`vm_pgmajfault_total`), reads and read latency (`disk_rd_*`; bench 6's `A6/bin/faults.py`); the folio census (`.folios.txt`): resident pages, pages in large folios, the largest order, per node and census time.
6. The course through B2 (300-s buckets and ten-minute quarters): writes per transaction, syncs per output and commit ms per output against the store's size. Bench 6 run 2's commit rose from 54 to 98 µs per transaction as its database grew (cross-unit notes): give this run's course, not a model.
7. The restarts: validator-05's and the observer's writes per minute in their second process against their first, and their `opening database`, `reth datadir: storage layout` and `keeps its storage layout` lines.
8. The store's failure signals: no `every later write and commit fails` and no `the final sync failed` line; `reth_db_latched` 0 on all eleven nodes; `reth_db_timed_out_not_aborted_transactions` and the largest `reth_db_oldest_reader_age_seconds` per node.
9. One table in `disk.md`, "measured in bench 6, not measurable on tn-lmdb": amplification as device bytes over page bytes (the node logs no page counts; `arms.json` reads n/a), prefault writes against growth (`page_prefault`, `mdbx_last_pgno` gone), the random-access advice (`mdbx_random_advice` gone), run 1's writes model (MDBX page arithmetic). Name what stands in for each, or "none".
10. State in `disk.md`: the CSV's disk counters are the whole disk under `/var/lib/telcoin` (logs, the consensus store and every other writer count too), so writes per transaction are an upper bound for the store's own; the store's own write count cannot be separated from the consensus store's on this harness.
