## Why

Bench 5 and bench 6 turned on one question: what the execution store does to the disk (bytes against write count against syncs on a provisioned-IOPS disk; whole-folio write-back; the page cache). The measuring tools were built for MDBX: `benchmark/node-persist-sampler.sh` (a per-node sampler installed at deploy step 9 when `BENCH_PERSIST_SAMPLER=1`), `benchmark/tools/folio-census.py`, the readers `benchmark/tools/arms-summary.py` and the log shapes in `benchmark/tools/log-shapes.txt`.
Bench 7's node stores execution state in tn-lmdb (`db/tn-lmdb.dat`, `tn-lmdb.dat.boot`, `database.version`) plus reth static files (`static_files/static_file_<segment>_<s>_<e>` with `.conf` and `.csoff`); change sets and senders go to static files, plain state is not written (storage layout v2). The architecture map says where persist and commit timing is logged and exported on the new build: `/home/drtnarg/coding/telcoin/telcoin-network-b7/.claude/project-context.md` (the storage, datadir and persist-timing sections; `tn_reth.persist_save_blocks_seconds`, `persist_commit_seconds`, the `persisted output` line's fields, `tn_engine.persist_duration_seconds`, the `output executed` line, the tn-lmdb `db.*` gauges; tn-lmdb's own `IoStats` are NOT exported by the node).
The user's standing rule for this program (2026-11-11): on a provisioned-IOPS disk the write COUNT and the syncs bind, on local NVMe the bytes; report both, always.
The inventory of every MDBX assumption in these tools: `benchmark/private/bench7-prep/design/inventory-publishing-and-machine.md` Part B item 7 (rows "Persist sampler", "Log shapes") .

## What to change

1. **`node-persist-sampler.sh`**: the device counters, memory and cgroup columns already work and stay. The five `mdbx_dat_*` columns are frozen names: keep them in the header, written empty on tn-lmdb. Add columns for the new store, appended at the END of the header (a frozen header only grows at the end; bump whatever version marker the header file carries and say so): size and allocated blocks of `db/tn-lmdb.dat`; total size and file count of `static_files/`; the page-cache residency of `tn-lmdb.dat` if the old MDBX column did the same for `mdbx.dat` with `fincore` (same tool, same cost); the store's used-bytes gauge on the new build if one exists (find the tn-lmdb `db.*` gauges' exported names in M's code; the old sampler read `tn_reth_mdbx_used_bytes`). The file to sample is chosen by what exists in the datadir (`tn-lmdb.dat` → the new columns, `mdbx.dat` → the old ones), never by a knob; a datadir with neither logs one line and samples the device columns only. **`stat`, `du`, `fincore`, `/proc/<pid>/io`, `/proc/diskstats`, the cgroup files and the node's own metrics endpoint are the only reads; nothing opens, maps or parses the store's files.** The per-process write counters must still separate the node's writes from everything else on the device.
2. **`tools/folio-census.py`**: it censuses which page-cache folios of `mdbx.dat` are large. Make the target file a parameter with the same auto-detection, keep its output format, add the static-file directory as an optional second target (summed), and make a row without data a clean empty row (bench 6's reader crashed on one: `benchmark/private/bench6-r20261113-2118/A4p/scripts/prefault_process.py` has the fix in its copy; the census itself must not emit a row a reader cannot parse).
3. **What the node itself reports per persist** on the new build: read M's `persisted output` line and the histograms (project-context names them; verify in `crates/tn-reth/src/env/execution.rs`); update `tools/log-shapes.txt` (the shapes the prefilter keeps: add the new build's lines, keep the old ones; the MDBX-advice lines simply never appear) and `tools/arms-summary.py` so that every storage figure it prints has a tn-lmdb source or prints `n/a` with the reason, never a zero that looks measured: device writes per transaction (count AND bytes), syncs per output, mean write size, the node's commit time per output, save-blocks time per output, the store's growth per transaction. Fields that existed only on MDBX (`page_newly`, `page_cow`, `mdbx_last_pgno`, `gc_entries`, `prefault_wchar_bytes`, the advice bytes) read as absent without a crash; a bench-6 results directory must still summarize exactly as before (a regression test over the existing fixture).
4. **The sampler's install step** in `benchmark-deploy.sh` (≈ :1773-1780) is another unit's file (HB-1). If the install line needs a change (a new dependency, a new argument), write the exact change in your hand-back; do not edit that file.
